# 2026-10-22 운영 지문·초과근무 실제 HTTP 경로 점검 (읽기 전용)

## 범위와 한계
- 운영 Supabase SongdoFood (`fnzgjidzdazlodmjhmes`) **통합 로그를 읽기 전용**으로 조회. UTC 2026-10-21 14:00 ~ 2026-10-22 14:00 (**한국 2026-10-21 23:00 ~ 2026-10-22 23:00**) 24시간 윈도우.
- `edge_logs`의 **REST RPC 경로명·HTTP 응답코드별 집계만** 조회. IP, 계정, 토큰, 실제 사진, 직원/근태 기록의 원문이나 내용은 열람·저장하지 않음. `postgres_logs`는 SQLSTATE/오류 종류별 수량만 확인.
- **이 수치는 서버가 HTTP 응답을 돌려준 횟수**이지 다른 이용자의 완전한 브라우저 동작, 응답 결과의 세부 payload, 실제 편집 후 UI 확인까지 보장하지 않는다. 서버에 도달하기 전에 UI 차단된 오류는 로그에 나타나지 않는다.

## 기간 안에 확인된 운영 경로
| Endpoint | HTTP 성공 | HTTP 실패 집계 |
|---|---:|---:|
| `list_my_fingerprint_records` | 220 × 200 | 집계상 0 |
| `save_my_fingerprint_photo` | 2 × 200, 2 × 204 = **4** | 집계상 0 |
| `get_my_fingerprint_photo` | 5 × 200 | 집계상 0 |
| `list_overtime_entries` | 222 × 200 | 집계상 0 |
| `save_my_overtime_entry_v2` | 2 × 200 | 집계상 0 |
| `save_my_overtime_day_v2` | **0 (조회 범위에 없음)** | 0 (조회 범위에 없음) |

- **중요:** `save_my_overtime_entry_v2`는 기존 초과근무 행의 완료 체크 경로이고, **계획시간 자체를 변경하는 `save_my_overtime_day_v2`와 별개**이다. 따라서 최근 운영 로그만으로 사용자에게 문제가 되었던 '초과근무 계획시간 수정 성공'을 증명할 수 없다.
- `save_my_fingerprint_photo`는 서버에서 성공 응답 받은 사례가 있다. 사용자 본인의 사진이 의도대로 표시되는지 또는 Android photo-picker/세션 복귀 경계에서 특정 사용자에게 실패했는지는 판단할 수 없다.
- 동 기간 `postgres_logs` 오류 SQLSTATE `42501` 71건 존재, 전체가 메시지상 'function' 계열로만 분류됨. 어느 RPC와 관련된 오류인지 **이 집계만으로 판별 불가**, 지문·초과근무 오류라고 주장하지 않음.
- 앞서 받은 격리시험 [운영 SQL 원본 지문 37/37](https://github.com/ahnbest23-hash/workmoa-backend-private/actions/runs/39771691566), [운영 SQL 원본 초과근무 40/40](https://github.com/ahnbest23-hash/workmoa-backend-private/actions/runs/39771123060), [진짜 Chromium 화면→가짜 서버·PostgreSQL 96/96](https://github.com/eco-i/eco-i.github.io/actions/runs/39783806135)과 **운영 로그의 의미는 분리**해야 한다. 가상시험 통과는 운영 앱 저장 성공 인증이 아니다.

## 복구 판정 및 다음 실사용 확인
1. 운영 앱 `main`은 이번 점검에서 수정하지 않았음. 운영 송도 DB 변경 0, 직원 실기록 쓰기/열람 0.
2. 실제 계정/실제 핸드폰에서 **기존 지문 기록 목록 읽기·사진 보기**는 직원이 원하면 쓰기 없이 확인 가능. 지문 *등록/교체* 재현은 사용자가 실제 등록 의도가 있는 사진으로 직접 수행할 때만 확인하며, 단순 시험을 위해 실제 기록 변경을 강요하면 안 됨.
3. **초과근무 계획시간 수정**은 실제 동작 여부에 대한 근거가 아직 없음. 사용자가 실제로 수정할 근무기록이 있을 때 현지 저장 → UI 재조회 → 확인하도록 하며, 예상되는 변경과 다른 저장·삭제를 만들지 말 것. 오류 재발 시 사용자 시각/화면 오류 문구만으로 원인별 요청 경로를 대조. 액세스토큰, 직원 사진, PIN 및 민감 기록 요청 금지.
4. 새로 설치한 휴근/연차/장기재직 7 RPC는 설치/권한/기존 데이터 불변까지 확인했으나 실제 사용 E2E는 미검증. 고위험 잔여 RPC 14종은 사용자 별도 승인/격리 검증 없이는 설치 금지.
5. 공식 3차 `3-8-53` 완료, `3-8-54` BLOCKED, 제품결함 37, **NOT CLEAN**. '지문·초과근무 복구 완료'라고 하지 말 것.
