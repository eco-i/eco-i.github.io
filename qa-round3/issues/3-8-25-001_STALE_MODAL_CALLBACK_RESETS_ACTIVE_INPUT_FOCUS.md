## 실제 소스 기반 격리 재현

GitHub QA 버전 `32b345b52f33de26fb17d88655abca9ee24385cc`의 원본 `openBackdrop`, `closeBackdrop`, `topOpenBackdrop`, `focusTopBackdrop`, `syncBackdropAccessibilityStack` 함수를 가짜 HTMLElement·DOM·타이머로 실행했다.

1. A 팝업을 연 같은 흐름에서 A 내부 두 번째/세 번째 입력 요소로 `focus()`를 지정하고, `openBackdrop`에 예약되어 있던 0ms 타이머를 수행하면 기존 코드는 무조건 `focusTopBackdrop(A)`를 다시 호출하여 첫 요소 A0으로 포커스를 되돌린다.
2. A→B를 빠르게 열어 B 내부 두 번째 요소를 지정했어도 B의 열기 콜백이 B0으로 재설정한다.
3. A→B 후 A 닫기 콜백이 남은 동안, B 안에서 B2를 선택하면 기존 닫기 콜백은 `focusTopBackdrop(B)`를 무조건 실행해 B0으로 되돌린다.
4. A를 닫자마자 재열기, A/B/C 내부중간 팝업 닫기에서도 같은 증상이 생길 수 있다.

원본 vs 수정 후보 비교 15개 동작에서 원본 **9/15**, 후보 **15/15** 기대 결과. 이는 실제 앱의 물리 키보드 사용자 상호작용 빈도 측정이 아니라 실제 GitHub 함수의 격리 재현임.
