# 근무모아 — 최신 미설치 RPC 26종 복구 수용설계 및 독립 QA 진입 기준 (2026-10-21)

> **범위:** 공개 가능한 *시험 수용조건·의존성 체크리스트*만 작성. **비공개 함수 SQL 구현 설계/운영 정책 본문이 아님.** 운영 `main`, 실제 직원/근태 DB, Supabase SQL/RPC/배포는 변경하지 않았다. 공식 상태 **3-8-53 완료 / 3-8-54 미시작·보류 / 제품 결함 37종 / 전체 NOT CLEAN**.

## 1. 입력 근거 — 반복 재조사 없음
- [26종의 공개 호출 인자·위치 정본](e2e/ci/missing-rpc-recovery-contracts.json), [서버 기존 구현 읽기 전용 보안 리뷰](LIVE_BACKEND_FUNCTION_BODY_SECURITY_REVIEW_READONLY_20261021.md), [정적 인자 보존 PASS](RPC_RECOVERY_STATIC_INTEGRITY_GATE_VERIFIED_20261021.md).
- 최신 26종 **실제 함수 원본 확보 0 / 운영 public 설치 0 / 운영 HTML 직접 호출 31곳**. 구버전 이름 22종(입력 불일치 19, 이름만 일치 3); 구버전도 없는 4종.
- 새 [개별 26종 수용시험표](e2e/ci/rpc-recovery-acceptance-matrix.json)와 [무인 정적 설계 검증기](e2e/ci/rpc-recovery-design-gate.mjs)는 원본 SQL 없이도 누락된 테스트 요구사항을 탐지한다. **통과하더라도 SQL 구현/실제 E2E 안전성을 증명하지 않는다.**

## 2. 26종을 기능별로 분할한 복구 수용조건

| 구분 | RPC 수 | 필수 검증 주제 | 검증 진입 전 제한 |
|---|---:|---|---|
| 인사·계정·인사 이력 | 5 | 서버 측 현재 관리자/세션, 발령일 경계, 이력 원자성, 동시 변경 중 권한 철회 | 실제 SQL 정본·세션 계약 없음 |
| 관리자 PIN 초기화·미리보기 | 2 | PIN 별도 확인, 최종 관리자 보호, 초기화와 세션 철회/미리보기 사이 revision | 실제 PIN/직원 행 금지 |
| 전체 초기화·백업/복원·미리보기 | 6 | 미리보기 무쓰기, preview→apply 버전 재검사, 참조 무결성, 전체 롤백 | 실 데이터 복제 금지 |
| 본인 데이터 복원 | 1 | 본인 범위, 업로드 구조, 동시 revision, 부분 성공·실패 차단 | 합성 자료만 |
| 휴일근무 | 5 | 날짜·조 편성·시간 범위, 소유자, ID+갱신시각 비교, 관리자와 직원 경합 | 구버전 단순 대체 금지 |
| 회사 일정 | 2 | 관리자 확인, ID/갱신시각 CAS, 범위·이력 정합 | 구버전 단순 대체 금지 |
| 개인 메모 | 3 | 자기 기록만, 단건·다건 삭제의 부분 성공 차단, stale/초안 보존 | 구버전 단순 대체 금지 |
| 연차 기준 | 1 | 연도·분 단위 정합, 이전 상태 비교, 충돌 시 무쓰기 | 구현 미확보 |
| 장기근속 설정 | 1 | 입사일·제외기간·사용분 정합, 동시 변경 거부 | 구현 미확보 |
| **합계** | **26** | **P0 14종 / P1 12종** | **실제 서버 검증 미착수** |

- **21종은 변경 함수**, **5종은 조회/미리보기**. 조회/미리보기 함수는 변경행·감사쓰기 등 어떠한 DB 부작용도 없어야 하며, 접근 가능한 정보의 역할/본인 범위를 재검토한다.
- **변경 함수 19종은 `p_expected...` 계열 비교 입력을 가진다.** 비교키가 클라이언트에서 전송된다는 사실만으로 CAS 구현 보장을 할 수 없으며, DB 트랜잭션 내의 버전·대상·권한 재검사와 충돌 거부를 실증해야 한다.
- **특별 차단 2종:** `admin_cancel_personnel_batch_v2`, `admin_set_holiday_work_enabled_v2`는 클라이언트 계약에 expected-state 인자가 없다. **동시수정 안전성의 서버 설계가 미해결**이며, 테스트 없이 구버전 forwarding/덮어쓰기/정상 판정 금지.
- `preview_data_restore_v2`의 사용자 역할별 미리보기 범위는 이름/인자만으로 확정할 수 없어 **권한 시나리오 확인 필요**로 명시했다.

## 3. 개발 전 필수 신뢰·보안 수용 기준

1. **원본 정본과 격리:** 누락 함수 원본 0종 상태를 유지해 표시하고, 운영 구버전 함수 정의는 참고 근거로만 사용. 검토된 **비공개 구현 소스 관리 경로**가 정해지기 전에는 SQL 본문을 공개 저장소/Actions에 저장하지 않는다.
2. **서버 신원·권한:** 요청의 `p_token`만 믿거나 UI 관리자 표시만 신뢰하지 않는다. 모든 RPC에서 최신 세션, 퇴직/잠금 상태, 서버 측 관리자/본인 범위를 확인. `SECURITY DEFINER`인 경우 함수 내부 권한 검사, EXECUTE 역할, search_path 및 RLS 우회 가능성 별도 검토.
3. **동시성:** 변경 전 expected 값과 DB 현재 상태 비교는 **같은 트랜잭션에서 원자적으로** 이루어져야 함. 서버가 먼저 커밋한 변경을 오래된 요청이 조용히 덮어쓰면 실패. 조/일근/휴근 정합도 같은 충돌 경계로 확인.
4. **복원/초기화:** 미리보기와 적용 사이 다른 관리자가 기록을 바꾼 경우 적용 거부. 비정상 payload, 중간 실패, PIN/권한 철회가 있으면 **전체 취소/롤백**, 기존 직원·이력·식별관계 무손상. 감사기록과 DB 본문 커밋의 정합도 확인.
5. **오류와 화면:** 401/403, 404(PGRST202), 409(CAS 충돌), 네트워크 지연/시간초과를 나눠 UI에 표시하고 수정 중이던 입력을 보존. 합성 테스트 404/409 PASS를 서버 원본 테스트 PASS로 승격 금지.
6. **운영 데이터 완전 배제:** 독립 DB, 가상 직원·가짜 PIN·가짜 사진만. 운영 프로젝트 클론, 실제 직원 정보, 운영 키·세션·RLS 원문 반출 금지. 운영과 구분되는 QA endpoint/키 확인 및 운영 호스트 요청 0이 필수.

## 4. 독립 QA 환경 순서 및 중단 조건
1. 비용이 없는 GitHub Actions·일회용 PostgreSQL/PostgREST/합성 인증을 우선 활용하되, **가짜 인증/일부 fixture만 통과하면 전체 E2E가 아니다**. 실제 Auth/RLS/역할/EXECUTE 검증에는 그 기능이 재현된 독립 환경이 필요하다.
2. **기존 테이블 27개의 민감 구조를 그대로 공개하지 않는** 별도 QA 전용 최소 스키마와 실제 신규 26종의 *검토된* SQL 구현을 **비공개 경로에서 준비**. 스키마/권한/반환 계약의 부족한 근거는 `BLOCKED`로 기록.
3. 26종 전부에 대해 격리 QA 함수 단위 테스트: 정상·무권한·타인소유·정지/권한회수·입력오류·중간실패·롤백·동시 요청·오래된 revision·재시도·응답형·조회 후 DB 원형 확인.
4. 운영 원본 아닌 임시 SQL을 테스트하는 경우 결과를 `SYNTHETIC_FIXTURE_ONLY`로 구분. 실제 인증/권한/SQL 원본과 앱 UI가 연결된 후에만 `REAL_ISOLATED_BACKEND_E2E` 증빙으로 분류.
5. [기존 E2E 실행계획](e2e/E2E_RUNBOOK.md)의 P0 5/P1 3 실증 완료 전 `3-8-54` 시작·CLEAN 선언·운영 배포 승인 금지. 민감 쿼리·운영 SQL 적용은 **별도의 명시적 승인** 필요.

## 5. 자동검사 범위와 통과의 의미

- 신규 [Actions 설계 수용검사](../.github/workflows/workmoa-qa-rpc-recovery-design.yml): `qa-3-8`만, 무료 Linux/Node 22, no secrets/no SQL/no DB connection, 안전한 결과 7일 저장.
- 함수 26종 누락·중복, 21 변경/5 조회, 위험수준 P0/P1, 원본 인자표와 expected 키 불일치, CAS/관리자/본인/복원 시험 누락, 원본 미확보·E2E 미완료 사실을 임의로 PASS로 고치는 행위를 **fail closed**.
- 별개의 [정적 호출 계약 검사](RPC_RECOVERY_STATIC_INTEGRITY_GATE_VERIFIED_20261021.md)가 GREEN이어도 **운영 서버 26종 이름 불일치 배포 차단 RED는 유지**한다.
- 이 문서는 **실제 26종 SQL 재구현/서버 설치/브라우저 full-stack E2E 완료를 주장하지 않는다**.

## 6. 보류한 구현 의사결정 (근거 없이 자동 결정하지 않음)
- 누락 26종의 반환형/오버로드/exception 코드, 세션 및 관리자의 정확한 보안 계약, UI 단계에서 요구하는 실패 식별 코드.
- `p_expected`가 없는 변경 RPC 2종을 어떤 서버 잠금·버전전제·UX 확인과 결합할지.
- 검토된 **비공개 구현 소스 저장소/승인**과 독립 QA 실행환경·비용/권한.
- 최신 SQL 원본이 존재하지 않으면 **새 구현 개발**이 필요하다는 사실을 정식 결정하고, 기존 구현과 동일하다고 가정하지 않을 것.
