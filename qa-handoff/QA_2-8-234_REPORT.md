## 2. 확정 제품 결함 및 수정
**제품 결함 1종: 공유 로그인 세션의 두 탭 동시변경 잠금 상호배제 실패**.
- 수정 전 실제 같은 출처 Chromium 2탭의 `acquireSharedSessionMutex()` 직접 동시획득 150회 중 **84회 두 탭이 모두 성공**. 기존 `localStorage` 검사/UUID 우선순위만으로 원자적 진입 보장 불가.
- 임시 스냅샷 열거·동기 지연·2단계 로컬 저장소 잠금 실험 또한 재현 실패. **모두 폐기한 뒤 공식 기준본에서 새로 수정함**.
- 공유 토큰·관리자 unlock·로그아웃 tombstone의 동기 read-modify-write 경로를 `navigator.locks.request()` 브라우저 원자 잠금으로 감싸고, 잠금 외부에서는 공유 변경 진입을 거부. 로그아웃·새 로그인·관리자 인증·자동업데이트 handoff·레거시 이관·지연 정리 경로에 적용. 짧은 동기 임계영역에서만 내부 허용 플래그를 유지.
- Web Lock 대기 도중 사용자가 로그아웃하거나 로그인 재시도한 경우 구형 요청이 저장되지 않도록 **잠금 획득 직후 `loginAttemptSeq`·`state.sessionToken` 재검증**.
- 로컬 미리보기 복구 실패 cleanup도 옛 토큰을 캡처하도록 보강하여 신규 로그인 토큰 오삭제 방지.

## 4. 명시적 미검증·배포 주의
- 운영 Supabase / RLS / 실제 관리자·직원 계정 경합 / 데이터 백업 복원, 실제 Android 카메라/OS 피커, BFCache·실기기 PWA, 여러 실제 기기 서버 동시 변경은 이번 로컬 테스트로 통과 선언하지 않음.
- 브라우저 Web Locks API 미지원 환경에서는 **공유 세션 쓰기를 fail-closed** 처리한다. 해당 구형 환경의 정상 로그인/사용성은 검증되지 않았으며 배포 전 별도 결정·시험이 필요하다.
